# Live test with associate, 2026-11-18

`evidence check` and `evidence grade` were run on exports from live associate
runs. Each row below is one run, not a rate.

## Setup

- Harness: associate at commit `6db92e2` (branch `clef/accuracy`, which holds
  `main` at `266dad3` plus documents only), pi 1.5.2, report mode.
- Models: `worker` and `cortex`, three read-only tasks each, on a scratch clone
  of this repository at commit `65388a7`. Timeout 1500 seconds per run.
- Tasks: `vectors` (count the entries of four lists and name a function),
  `settings` (report three settings, a loader and a constant), `review`
  (three yes/no questions about `evidence/answer/`).
- Expected values for the answer check were written before the runs started.
- Commands under test: this branch at commit `024c92b`.

- `evidence grade` agreed with a hand reading on the three answers it was given.
  Three answers is too few to say anything about the answer check in general.

## Findings

1. **Stated conclusions were shown as if backed (fixed in `024c92b`).** The
   worker `vectors` run stated five conclusions as supported; four rested on
   refused facts. The report printed only the stated counts. It now prints how
   many the re-check backed and refused, with a test.
2. **The answer check can be satisfied by text the harness wrote (open).** The
   answer file associate renders (`answer.md`) holds lines such as "2 items were
   refused" and "Finish summary (3 sentences)". A deliberately wrong answer
   (5 and 7 where 2 and 3 were expected) was reported as holding 2 and 3 when
   those lines were present. Bare small numbers are weak expected values, and
   the text given to the answer check should be the model's answer without the
   harness's own lines. Which text is graded is decided by the caller.
3. **An answer that is correct only in unchecked text still matches (by
   design).** In the worker `vectors` run the four counts were refused as facts
   and appear only in the model's own final message, which `answer.md` carries
   under an unchecked label. The answer check read them there. The two results
   are separate: the run check says the counts had no quote behind them, the
   answer check says the stated counts equal the expected ones.
4. **Half the runs left nothing to check (an associate matter).** The worker
   `review` run called `finish` twice with its facts as one quoted string
   instead of a list; both calls were rejected and the run ended at the timeout
   with its answer lost. The two cortex runs timed out while still checking
   quotes (106 and 48 calls). See associate issue 22.
